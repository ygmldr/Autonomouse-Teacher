- `step/start`, `request/header`, `llm/retry`, `assistant/message`, and stream frame notifications are observations, not transactional budget reservations. A step/header may be logged before the model runs; it does not prove billing occurred. Failed attempts can have provider usage without a successful final assistant message.

### Critical internal HTTP gap and strict text-only closure conditions

One global `llm/stream` call can cause **more than one model POST**: [DeepSeek adapter:105–162](../artifacts/sdk-probe/upstream/dsh-llm-deepseek/src/adapter.ts#L105-L162) loops around `/messages`; stale uploaded image IDs can cause `files.retry(detail)` to `continue` **inside** the stream. [RequestFiles:130–143](../artifacts/sdk-probe/upstream/dsh-llm-deepseek/src/request-files.ts#L130-L143) permits at most one stale-ID retry. Image upload/recovery uses additional Files HTTP operations. They are not automatically separate stream-hook invocations or entries in Python's request count.

A source-based M0 **text-only** restriction can close this specific path only if all of these are enforced and later tested, not merely because the first prompt is text:

1. Freeze the exact official direct DeepSeek API-key adapter, route/model, tools, extension providers and source/hash; exclude alternative adapters, arbitrary execution/network tools, model-selection changes, plugins with direct HTTP/SDK calls, and external Judge paths.
2. In the global **pre-adapter** waterfall, traverse the complete assembled `options.messages` history, including every tool result and auxiliary/compaction call. Allowlist explicit block/role/key shapes and tool names; reject `image`, `file`, attachment-bearing objects, unknown block tags/extension structures, and any nested non-text payloads. Do not rely on request projection to strip them after authorization. Permit only necessary text/reasoning/tool-call/control blocks with `skill_lookup` names/arguments validated; tool results must render fixed JSON **text**. Pin the effective tools/toolHistory surface, provider/model, explicit bounded maxTokens, required known sessionId and allowed purpose. Fail closed on absent/unknown attribution or bounds.
3. Require the gate to be the outermost/first middleware (`prepend`/frozen load order), and ensure every inner listener is audited to preserve the guarded request (not replace content, change route, short-circuit billing or dispatch another unguarded call). ### Minimal future budget integration (NOT implemented)

A separately reviewed/frozen plugin can use global `llm/stream` to create a unique reservation **before** calling/iterating `next()`, against a single trusted transactional ledger shared across processes/restarts. Validate actual route/model/purpose and worst-case full-context/output prices; atomically reserve both money and total input/output/request counters, with reentry/concurrency-safe identities. No ledger availability / unknown pricing / route drift means denial, not fallback. Persist denial independently of event delivery and Python timeouts. Compaction and same-step retries each need fresh reservations, while step caps and per-provider retry policy are additional controls. Count/reserve any bounded internal transport retries conservatively or enforce a transport-level proxy; do not promise generic per-billable-attempt guarantees from a stream hook alone. This must not unlock today's production Gate or change the first-round accounting claims.
